# Compliance pack

The documents a club needs before the first real person is entered (engineering standards S9.7, ENG-09, phase E5).
Each document is a **draft until the product owner approves and dates it** in its status line (ENG-TEST-14); the
club, as controller, adopts the records of processing, the DPIA and the data-subject procedure as its own.

| Document | S9.7 item | Status |
|---|---|---|
| [`ropa.md`](ropa.md) | records of processing (art. 30) | draft |
| [`dpia.md`](dpia.md) | DPIA (art. 35) | draft |
| [`processors.md`](processors.md) | processor and recipient register | draft |
| [`breach-register.md`](breach-register.md) | breach register (art. 33(5)) | draft, empty |
| [`retention.md`](retention.md) | retention schedule (S9.5) | draft |
| [`data-subject-requests.md`](data-subject-requests.md) | data-subject request procedure | draft |
| [`asvs-checklist.md`](asvs-checklist.md) | OWASP ASVS 5.0 level 2 map (S8.1) | draft |
| [`legal-verification.md`](legal-verification.md) | verified legal claims (S9.10) | awaiting the owner's acceptance |
| privacy notices | Polish, English, short version for children | E19-S03 (#469) |

Out of scope here: the data processing agreement between the host and the club (who signs it is open, ENG-Q-03).

## Before the pilot data gate

Every document approved and dated, and the open items marked as blocking the pilot data gate closed — in
particular the DPA (P-0) and the transfer mechanisms of Railway and Resend (P-1a, P-2a).
