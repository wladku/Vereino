# Backward Compatibility — Vereino

This file lists the **protected contract surfaces** of this repository: what counts as a breaking change, and what a breaking change must do before it merges. Review skills check diffs against it; implementation skills warn when a change violates it.

**Scope and precedence.** This file covers surfaces that Vereino owns or that Vereino tooling, CI and deployment depend on. Open Mercato's own surfaces are governed by `.ai/guides/upstream/BACKWARD_COMPATIBILITY.md` (shipped by `create-mercato-app@0.9.0`, see `.ai/guides/upstream/manifest.json`); where the two disagree, the upstream file wins for `@open-mercato/*` surfaces. Normative sources: engineering standards S1.3, S3.7, S5.4, S6.9, S6.10, ADR-013, ADR-021 (`.ai/specs/2026-10-21-engineering-standards-and-patterns.md`), and the club spec's *Architecture → Compatibility* (`.ai/specs/2026-10-20-vereino-club-management.md`).

## Default path for a breaking change

1. **Prefer additive.** New field, new route, new ID, alias. Additive changes need none of the steps below.
2. **Bridge.** Keep the old name, path, field or ID working next to the new one for at least one minor release (S6.9); mark it `@deprecated` with the target removal version (S3.7) and, for routes, `deprecated: true` in `openApi`.
3. **Mark it.** Conventional Commit with `!` and a `BREAKING CHANGE:` footer (S1.3); release-please bumps the major version, or the minor while below `1.0.0` (S6.10).
4. **Document it.** `CHANGELOG.md` entry with operator upgrade notes (ADR-021). release-please writes the entry from the Conventional Commit title and its `BREAKING CHANGE:` footer; until the first release pull request has created `CHANGELOG.md`, also record the change in the PR description and the governing spec's changelog.
5. **Spec.** A Changelog row in the governing spec (S1.6) and a *Rollout, Migration, and Rollback* note; tick the PR template box "Contract surface changed?" (`.github/PULL_REQUEST_TEMPLATE.md`).
6. **Ask first.** Public contracts, migrations and DB targets are Ask First (`AGENTS.md`).

Before the first deployment, a Vereino-owned surface with only in-repo consumers may change in one PR that updates every consumer, with step 5 still required.

## Surface inventory

### 1. Workspace package exports — `@vereino/core`, `@vereino/db`, `@vereino/ui`
- **Where:** `packages/{core,db,ui}/package.json` → `"exports": { ".": "./src/index.ts" }`; each `src/index.ts` is currently `export {}`. Only consumer: `@vereino/app` (`workspace:*` in `packages/app/package.json`, `transpilePackages` in `packages/app/next.config.ts`, `@source` for ui in `packages/app/src/app/globals.css`). Not published.
- **Breaking:** removing or renaming an export; narrowing a signature or type; adding a subpath to `exports` (invites deep imports, which `AGENTS.md` forbids); a package importing `@vereino/app` or reversing `app → ui | db → core`.
- **Path:** internal; change all call sites in the same PR; `yarn typecheck` and `yarn typecheck:packages` must pass. Becomes a public contract only if a package is ever published (**Gap:** no plan in the repo).
- **`foundation` module helpers:** the TypeScript API that `packages/app/src/modules/foundation/index.ts` re-exports (`authorizeScoped`, `assertInScope`, `scopeContract`, `seedRoles`, `syncAuthRoles`, `createAccount`, `encryptedField`, `registerModuleSchedule`, `renderLocalized`, `errors`, …) and imported by other modules only as `@/modules/foundation` is an **internal** surface under the same rule: a change lands with every consumer in the same PR and `yarn typecheck` is the guard; no additive-only promise. Its DI token `vereino.scopeProvider` and its error codes are protected under §4 and §3.

### 2. HTTP API routes and OpenAPI
- **Where:** none Vereino-owned yet. Planned under `packages/app/src/modules/<id>/api/**/route.ts` (`makeCrudRoute`, per-method `metadata`, separate `openApi` export; catalogue in club spec *API, Command, and Error Contracts*, e.g. `/api/club_core/sections`, `/api/people/me`). OpenAPI is served by the `api_docs` module (`packages/app/src/app/api/docs`). The scaffold modules `example`, `example_customers_sync`, `ratelimit_probe` are **not** Vereino-owned (S3.1) and are not enabled in `src/modules.ts`; `agent_examples` was deleted with the enterprise package (ENG-Q-10, #466).
- **Platform URLs relied on now:** `/api/healthz` (`railway.toml` health check, S15.4); `/login` (readiness probe in `.github/workflows/ci.yml` jobs `browser-smoke` and `perf`).
- **Breaking:** removing or renaming a path or method; removing or renaming a response key; narrowing a request field (optional → required, wider → narrower enum); changing the list shape `{ items, total, page, pageSize, totalPages }` (S6.4), the error body `{ error, code }` (S6.7), camelCase keys, ISO 8601 UTC instants, integer grosz + `currency` (S6.3–S6.6), or 400 (missing lock token) / 409 (stale `updatedAt`) semantics (S5.2); accepting `tenantId`/`organizationId` from the payload.
- **Narrowed guarantee — `placeId` (2026-11-17, #270; approved on #252, parity spec A *Compatibility*):** a session or a one-off activity may take place at a typed venue (`venue: { name, address }`), and then `placeId` / `defaultPlaceId` is `null` in every read of `activities` (`/api/activities/activities[/{id}]`, `/occurrences[/{id}]`, `/calendar[/{id}]`, `POST /events`, conflict lists) and in the DI services `activities.scheduleDirectory`, `activities.publicSchedule` (the series and session rows) and `activities.shareText`; `activities.placeSessions` selects by place and never returns such a session. Before the first deployment every in-repo reader was updated in the same PR (the list is in the PR); a reader added later must handle `null`. Rollback rule: before redeploying a release older than migration B (`Migration20261117110933_activities`), cancel the typed-venue sessions or give them a place (the query is in the migration's `down`).
- **Narrowed guarantee — one-off events and opening hours (2026-11-18, #288; approved on #253, facilities parity spec *Compatibility*, DD-R15):** `POST /api/activities/events` with a `placeId` refuses an event outside the place's opening windows of its day (own or inherited) with 409 `event_place_closed` (`field: "startsAt"`, `opening: [{ from, to }]`). A caller that booked events outside the hours gets that 409. No stored data changes, and rolling back restores the old acceptance. A typed venue and recurring series are not checked.
- **Behaviour change — former persons leave the people list (2026-11-18, #306; approved on #255, item 9 of the people life-cycle spec *Rollout*):** `GET /api/people/persons` gains the optional `view=former` (persons whose `leftOn`, a new list and detail key, is today or earlier) and leaves former persons out of every other view; a name `search` in the plain list (no `view`) still finds them. The audience expansion of `@vereino/core` (`expandAudience`, the optional `AudienceContact.leftOn`) reaches no former person, as a member or as a guardian, and the pickers that read this list follow it. No key is removed and every existing request stays valid; a reader that must see everyone asks the `former` view as well.
- **Behaviour change — anonymised persons read "Former member" (2026-11-20, #308; approved on #255, items 2, 5 and 7 of the people life-cycle spec *Rollout*):** `GET /api/people/persons` and `/api/people/persons/{id}` gain `anonymizedAt` (and, with `people.manage`, `erasureHoldUntil`); for an anonymised person `firstName` is the localised "Former member" and `lastName` is empty, unless the reader has `people.manage` and the name is still kept under the retention hold. The DI `people.personDirectory.findPersons` returns the same label (with the optional `anonymized: true`) and `searchPersonIds` never returns an anonymised person. New routes `POST /api/people/persons/{id}/anonymize` and `DELETE /api/people/persons/{id}`, the event `people.person.anonymized`, the first emission of `people.person.deleted`. No key is removed; a reader that showed names keeps working and shows the label.
- **New contract — person data export document (2026-11-22, #527; approved on #527, person data export spec DD-X02):** `GET /api/people/persons/{id}/data-export` (feature `people.persons.export`, `club_admin` grant) returns the JSON document `format: "vereino.person-data-export"`, `version: 1` (`subject`, `sections[] { module, table, activity, portable, rows, omittedOtherAuthors?, reviewFields? }`, `actorCounts`, `reviewRequired`, `omitted`). A person who received the file may feed it to another system, so the shape is versioned: adding a section, a table, a row key or an `omitted` reason is additive; removing or renaming a top-level key, a section key or a reason, or changing their meaning, needs `version: 2`. The DI tokens `people.dataExport.<module>` (contract `PersonDataExportContributor` in `people/services/data-export.ts`) and the `foundation` helper `personDeliveriesForExport` are new internal seams. The append-only table `people_data_export_log` is new (§5).
- **Path:** default path; no URL versioning (S6.9). **Gap:** OpenAPI diff gate (`oasdiff`) once `api_docs` can emit a file (S6.9, after E3); until then review enforces it.

### 3. Machine error codes
- **Where:** `packages/app/src/modules/<id>/lib/error-codes.ts` (`errorCodes` array), checked by `yarn contracts:check` (`packages/app/scripts/check-vereino-contracts.mjs`): lower snake_case, unique app-wide, reserved platform codes rejected, `messageKey` present in `en` and `pl`.

### 5. Database schema and migrations
- **Where:** MikroORM 7 + PostgreSQL 17 (pgvector image). Entities in `src/modules/<id>/data/entities.ts`; migrations `src/modules/<id>/migrations/Migration*.ts` with `.snapshot-open-mercato.json`. Today only the non-Vereino scaffold modules `example` and `example_customers_sync` ship migrations, and they are not enabled.
- **Breaking:** editing a migration merged to `main` (immutable, S5.4); renaming or dropping a table or column; narrowing a type; adding a NOT NULL column without default to a populated table; changing the standard columns (`id`, `tenant_id`, `organization_id`, `created_at`, `updated_at`, `deleted_at`).
- **Path:** corrective migration only; expand/contract across two releases (add nullable → backfill → enforce → switch code → drop later); drop needs a product-owner decision and a verified backup; `lock_timeout = '5s'`; `CREATE INDEX CONCURRENTLY` in its own idempotent migration; `down()` for additive steps; value rewrites on indexed entities declare `declareQueryIndexReindex`; new encryption maps on deployed modules ship backfill SQL (S5.6). Migrations are CODEOWNERS paths and Ask First before commit. Rollback never runs `down()` (S14.6).

### 6. i18n keys and locales
- **Where:** each Vereino module's `i18n/en.json` + `i18n/pl.json` (both required; key parity checked by `yarn contracts:check`; hard-coded strings by `yarn i18n:check-hardcoded --strict`). App catalogs `packages/app/src/i18n/{de,en,es,ko,pl}.json` are platform-owned.
- **Breaking:** removing `en` or `pl`; removing or renaming a key still referenced by code, `page.meta.ts` (`pageTitleKey`, `pageGroupKey`) or an error code's `messageKey`. Keys are internal: change them in the same PR as their references. Adding a locale is additive.

### 8. Configuration formats and environment
- `.ai/agentic.config.json` (`"version": 1`; keys `baseBranch`, `tracker`, `browser`, `validation`, `labels`, `qaGate`, `engine`, `reviewChecklist`, `paths.*` read by `om-*` skills; tracker and browser descriptors in `.ai/trackers/`, `.ai/browsers/`). Change via `om-setup-agent-pipeline`, bump `version` on incompatible change.
- `packages/app/vereino-modules.json` (`modules` array read by lint, format, i18n, coverage and `contracts:check` through `packages/app/scripts/vereino-paths.mjs`).
- `packages/app/.env.example`: variable names are platform-owned (`DATABASE_URL`, `JWT_SECRET`, `AUTH_SECRET`, `TENANT_DATA_ENCRYPTION_*`, `OM_*`). Vereino variables use the `VEREINO_` prefix and are protected from first deployment (S6.9, S8.10). So far `VEREINO_IT_POSTGRES_IMAGE` (test runner), `VEREINO_SMOKE_EMAIL` / `VEREINO_SMOKE_PASSWORD` (`scripts/smoke.mjs`), the optional operations variables `VEREINO_OPS_WORKER_HEARTBEAT_URL`, `VEREINO_OPS_BACKUP_HEARTBEAT_URL` (E18-S04, `docs/ops/monitoring.md`) and `VEREINO_OPS_PAYMENTS_INVARIANTS_HEARTBEAT_URL` (#531) and `VEREINO_HOME_CLUB_SLUG` and `VEREINO_CLUB_DOMAIN` (below), all listed in `.env.example`. The alert tokens `vereino.ops.backup.failed` of `packages/app/scripts/vereino-ops-signal.mjs` and `vereino.ops.payments.invariants.drift` of `payments/lib/invariants.ts` are what the alert filters match, so renaming one is breaking. The boot check (`packages/app/scripts/vereino-boot-env.mjs`) refuses to start without a required variable: making a variable required is a breaking change for every environment that lacks it. Since #738 it also checks the platform's rate-limit variables: `RATE_LIMIT_STRATEGY=redis` needs `REDIS_URL` (already required on Railway), and on Railway (`RAILWAY_ENVIRONMENT_NAME`) it refuses `RATE_LIMIT_STRATEGY` other than `redis` (the start scripts default to it), `RATE_LIMIT_ENABLED=false`, `OM_INTEGRATION_TEST` and `OM_TEST_MODE`; an unset proxy depth (`RATE_LIMIT_TRUST_PROXY_DEPTH`) only warns. Since #740 (key-store spec DD-K03) the optional `VEREINO_KEY_STORE` (`derived` default, `vault`) is protected: in `vault` mode the check requires `VAULT_ADDR`, `VAULT_TOKEN`, `LOOKUP_HASH_PEPPER` and `VAULT_KV_PATH` = `secret/data` (when set) and refuses the derived-key fallbacks (`TENANT_DATA_ENCRYPTION_FALLBACK_KEY`, `TENANT_DATA_ENCRYPTION_KEY`, `ALLOW_DERIVED_KMS_FALLBACK`) and `TENANT_DATA_ENCRYPTION` off; in `derived` mode it refuses `VAULT_ADDR` and `VAULT_TOKEN` (no environment sets them today); a `VAULT_REQUEST_TIMEOUT_MS` below 3000 in `vault` mode only warns.
- Social sign-in (#566, additive, `.ai/specs/2026-10-27-vereino-social-sign-in.md`): the optional `VEREINO_OAUTH_GOOGLE_CLIENT_ID`, `VEREINO_OAUTH_GOOGLE_CLIENT_SECRET` and `VEREINO_OAUTH_REDIRECT_BASE_URL` (Google disabled without the client), and the test-only endpoint overrides `VEREINO_OAUTH_GOOGLE_AUTHORIZATION_URL` / `VEREINO_OAUTH_GOOGLE_TOKEN_URL` (the integration runner's fake; also `VEREINO_QA_OAUTH_FAKE_PORT`, runner-internal). The callback path `/api/foundation/identity/google/callback` is registered in the Google OAuth client, so moving it is breaking. New protected surfaces of the same change: the routes `/api/foundation/identity/**`, the error codes `identity_provider_disabled`, `identity_unavailable`, `identity_already_linked`, `identity_last_method`, the events `foundation.identity.linked|unlinked|signed_in` (ids and provider only), the features `foundation.identity.self|manage`, the table `vereino_identity_links` and the injection spots `vereino:club:profile:sign-in` and `vereino:people:person-record:sign-in`.
- Social sign-in with Facebook (#567, additive): the optional `VEREINO_OAUTH_FACEBOOK_CLIENT_ID` and `VEREINO_OAUTH_FACEBOOK_CLIENT_SECRET` (Facebook disabled without them) and the test-only `VEREINO_OAUTH_FACEBOOK_AUTHORIZATION_URL` / `…_TOKEN_URL` / `…_USERINFO_URL`. The callback `/api/foundation/identity/facebook/callback` and the data-deletion callback `POST /api/foundation/identity/facebook/deletion` (answers `{ url, confirmation_code }`) are registered in the Facebook app, and the status page `/identity/deletion?code=` is the URL that answer hands to Facebook, so moving any of them is breaking.
- `VEREINO_HOME_CLUB_SLUG` (#485, additive; **deprecated** by #631, not removed): the public slug of the instance's club, which `/` leads a guest to while its page is published; unset, `/` leads a guest to `/login`. Read only while `VEREINO_CLUB_DOMAIN` is unset; removing it is breaking and needs its own deprecation release.
- Shared outline library (#685, additive, optional; training outlines spec phase 4, DD-O10): `VEREINO_LIBRARY_TENANT_ID`, `VEREINO_LIBRARY_ORGANIZATION_ID` and the secret `VEREINO_LIBRARY_RATER_SECRET` (one secret, or `v<n>:<secret>` versions separated by commas; a rotation adds a version and keeps the old ones, so a stored rater key never needs re-keying). Unset, the library is off: its routes answer 404 `library_not_configured` and everything else works. The library tenant is created by `yarn mercato training library-init`; renaming a variable or dropping a secret version is breaking (raters of that version lose their ratings' link). New protected surfaces of the same change: the routes `/api/training/library/**`, `/api/training/public/library/**` and `/api/training/outlines/{id}/publish`, the page `/library/o/{entryId}`, the club setting `outlineLibraryMaxVisibility` (`club`, `clubs`, `public`; default `clubs`), the features `training.library.use|publish`, the error codes `library_not_configured`, `visibility_above_club_level`, `library_terms_required`, `library_entry_not_found`, `outline_not_published`, `rating_requires_use`, `library_report_exists`, the tables `training_library_entries|ratings|uses|reports`, the CLI commands `training library-init|library-moderate`, the optional DI token `club_core.clubDeleteBeyondTenant.<module>` (`registerClubDeleteBeyondTenant` in `@/modules/foundation`) and the probe kind `library` of the route isolation inventory.
- `VEREINO_CLUB_DOMAIN` (#631, additive, optional; many clubs spec phase 3, DD-M02): unset, behaviour is unchanged. Set, a club is reached at `<public slug>.<club domain>` (scheme of `APP_URL`), `/p/<slug>` pages opened on any other host redirect there with path and query kept (DD-M03, approved 2026-11-23), the bare domain and `APP_URL`'s host show the neutral landing page, links in Vereino-sent e-mails use the club's address and the sender's display name is the club's. The public slug therefore becomes part of every club address: renaming a club's slug breaks its old links (as `/p/<slug>` already did). `DEMO_MODE` (platform variable) now defaults to off in the app code, `docker-compose.fullapp*.yml` and the production `Dockerfile` image (owner decision, #485; the platform's own setup code still reads an unset value as on, so the image sets it): an instance that relied on the unset default to show the demo widgets sets `DEMO_MODE=true`.

## How agents use this file
- **Review** (`om-code-review`, `om-auto-review-pr`, `om-pre-implement-spec`): map every changed path to a section above; a breaking change without the default path is a blocking finding.
- **Implementation** (`om-module-scaffold`, `om-data-model-design`, `om-auto-create-pr`, …): before editing a listed surface, state the tier and stop to ask the user when the change is breaking.
- Check the tier table first: before the first deployment, in-repo-only surfaces may change in one PR that updates every consumer.
- `AGENTS.md` currently points contract changes to the upstream file only. **Gap:** add a pointer to this file (Ask First).

## Breaking-change checklist
- [ ] Surface identified (section number) and tier stated.
- [ ] Additive alternative considered and rejected for a stated reason.
- [ ] Bridge in place for at least one minor release; `@deprecated` / `deprecated: true` with target version.
- [ ] Commit/PR title uses `!` and a `BREAKING CHANGE:` footer.
- [ ] `CHANGELOG.md` entry with operator upgrade notes (the `BREAKING CHANGE:` footer release-please copies; plus the PR description until the first release).
- [ ] Governing spec updated: Changelog row and *Rollout, Migration, and Rollback* note.
- [ ] Migrations: new corrective migration, expand/contract, no edit to a merged migration, SQL in the PR.
- [ ] Consumers updated in the same PR: code, `ci.yml`, `AGENTS.md`, `.ai/agentic.config.json`, README, `docs/ops/`.
- [ ] `yarn verify` green; `yarn test:integration:vereino --filter <TEST-ID>` for affected routes.
- [ ] User approval recorded for public contracts, migrations or DB targets.
