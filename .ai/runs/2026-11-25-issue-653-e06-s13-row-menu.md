# Run: issue #653 — the real fix behind the E06-S13 quarantine

- **Trigger:** cezar task for issue #653, re-queued by the owner on 2026-11-25 ("build the real fix, remove the `test.fixme` quarantine of E06-S13, and run the test locally several times before opening the PR").
- **Issue:** #653 (`bug`, `priority-high`, `risk-low`). Quarantine PRs #654 and #655 merged on 2026-11-22.
- **Branch:** `fix/issue-653-e06-s13-assign-substitute-menu` (cezar worktree `da57df48`).

## Steps

1. Read the two failing CI runs (45065537955, 44848338885): both fail at the `Assign substitute` menu item with "element is not stable" / "element was detached from the DOM" on the first attempt and the retry. Neither run contained the `toPass` retry from #652 (merged 2026-11-22T23:57Z, after both runs; the quarantine landed first), so that retry has never run in CI.
2. Root cause in our code: `SessionsList` (`activities/components/OccurrencesTable.tsx`) keys its `useQuery` on `useOrganizationScopeVersion()`. On a fresh page load the version is 0 and becomes 1 once the top bar emits the organization scope (`@open-mercato/shared/lib/frontend/organizationEvents.ts`). The new key has no data, `isLoading` turns true, `DataTable` drops every row, and the open `RowActions` menu, rendered with its row, unmounts. Rows from the first read were already on screen, so the test opened the menu inside that window. In addition, the feature check (`useActivitiesFeatures`) adds "Assign substitute" to the row menu only after it answers.
3. Fix: `placeholderData: keepPreviousData` on both occurrences list queries (`SessionsList`, `ActivitySessions`), as `ThreadsTable` and `AgeCategoriesTable` already do. The "started" moment used for the row actions now travels with the rows (`readAt` in the query result): with a placeholder `dataUpdatedAt` is 0, which would have judged every session as not started.
4. Test: removed `test.fixme` and the `// quarantine: #653` marker; the menu step returns early when the dialog is already open and opens the menu only when the item is not visible (lesson `datatable-row-menu-detaches-on-rerender`).
5. Updated lesson `datatable-row-menu-detaches-on-rerender` with the cause and a code rule.

## Decisions

- Fixed the list, not the platform `RowActions`/`DataTable` (read-only, upstream). No Ask First item: no contract, dependency, migration or module change; `@tanstack/react-query` is already a dependency of the app.
- Kept the `toPass` retry in the test: the hover menu can still close on scroll/pointer leave on a slow runner (lesson `row-actions-hover-menu-closes-on-scroll`), and the item still appears only after the feature check answers.
