### Blocking themes (deduplicated, verified)

1. **Treasurer role is not modelled** — REQ-034 assigns it "in the person record", but `people_role_assignments.role` has no `treasurer` and `scopeService` has no treasurer branch (empty scope, fail-closed); Phase 2 outcome, the backend navigation row "Administrator / treasurer" and UX UC-15/F-03 give the treasurer the coach units report and non-finance menus that DD-33 and TEST-046 deny. (A, B, C)
2. **Permissions that block declared screens** — the coach row lacks `people.self`/`communication.view` needed by `/club`; the coach's "whole club" facility calendar hits an API gated by place scope that only attendants have; `/club/cash` (`payments.cash.record`) reads charges through a route gated by `payments.view`. (A, C)
3. **Field and rule contradictions** — session coach is `coach_id` in rules/architecture but `coach_person_id` in the data model; section deactivation is both "409 with active groups" and "deactivation instead of deletion when it has groups". (A)
4. **Phase/test mismatch** — TEST-029 (phase 2) asserts a camp charge that exists only from phase 4, while Phase 2 claims to close REQ-018. (A)
5. **Missing screen and endpoint contracts** — `/club/payments/return` (M-09) and the guardian's order list (`GET /api/payments/order-campaigns?for=me` under `payments.orders.place`) exist in UX and mockup but not in the spec. (C)
6. **Platform rules** — "no operations in system scope" contradicts anonymous routes that must resolve a club from a globally unique slug or token hash before any tenant is known (needs a named installed contract or an explicit read-only lookup, V-12); the `facilities.internal_booking.created` subscriber writes "in the same transaction", against "effects stay post-commit" (move supersession into the command). (D)
