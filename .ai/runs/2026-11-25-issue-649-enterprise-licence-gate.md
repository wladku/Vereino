## Decisions

- **Production key list is empty.** The spec lists "the owner's first `kid`" as a phase 1a deliverable, but the signing pair is an owner action (phase 2, "the owner creates … the signing key pair") and a private key must never be generated by an agent. Until the owner adds the public half, every key is `unknown_kid` and every feature is `off` — the safe direction, and exactly the phase 1a exit gate (a test-signed key rejected on staging).
- **Test keys are trusted only through an explicit `extra` list** (filled by the `--ci` generated file in phase 1b) **and** `VEREINO_CI=true`; a `test-` kid in the compiled production list throws at boot.
- **`assertAvailable` added** next to the spec's `stateOf` / `isEnabled` / `assertWritable`: Enterprise read routes need the 404-when-`off` check without refusing reads when `read_only` (spec *Users, Permissions, and Scope*). `statusOf` exposes the renewal notice for module UIs.
- **Signature before shape:** a tampered payload is always `bad_signature`; a rejected key is logged by `lid` only when the `lid` is a safe identifier, else by position.
- **Wrong instance is a rejection** reported by the registry (`wrong_instance`), not silently filtered.
- **Keys read once per process**, on the first DI registration, as DD-E05 says; `licence-status` builds its own registry so it reports what the environment holds now.
